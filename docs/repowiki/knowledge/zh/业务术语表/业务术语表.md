### 热更包
- 定义：一次热更新的完整交付单元，存放于 `hotfix/<日期>-<序号>/` 目录下，包含 `hotfix.conf.lua` 元信息配置文件以及若干 `codeN.lua` patcher 脚本。服务端通过读取该目录完成校验、步骤编排和代码注入。
- 别名：hotfix_dir、patch

### hotfix.conf.lua
- 定义：热更包的元数据与开关配置文件，必填字段包括 `desc`、`checksum`、`gitsha_base`、`gitsha_update`、`time`；可选开关包括 `clearcache`、`reload_res`、`reload_sproto`、`reload_orm_schema`；`update_files` 列出要参与 checksum 校验的工程文件路径，`code_files` 列出本目录下的 patcher 脚本。
- 别名：热更配置、hotfix config

### patcher
- 定义：热更代码的执行单元，即 `codeN.lua` 文件，必须返回一个表，包含 `targets`（声明注入到的 skynet 服务名数组）和 `run`（在目标服务进程内执行的函数）。由 hotfix 服务加载后通过 skynet debug RUN 协议注入到目标服务执行。
- 别名：热更脚本、patch script

### GM 命令
- 定义：Game Master 管理命令，通过 HTTP `/gm/execute` 接口（GET/POST）或命令行调用，由 `.gm` 服务路由到具体 handler。热更模块通过 `gm_api.register` 注册 `hotfix`、`hotfix_history` 等命令，也调用 `clearcache`、`reload_res`、`reload_sproto_schema`、`reload_orm_schema` 等内置命令。
- 别名：gm指令、gm命令

### 热更历史
- 定义：每次热更执行后记录的步骤结果，保存在 hotfix 服务的内存表 `g_hotfix_history` 中，最多保留 100 条，重启丢失。可通过 `hotfix_history` 命令查询最近 N 条记录。
- 别名：hotfix_history、热更记录

### update_files
- 定义：热更配置中声明的、需要被整体替换的工程源文件列表（如 `lualib/cmd_api.lua`、`service/gm.lua`）。这些文件不参与热更包分发，仅参与 checksum 拼接校验；实际替换需运维先修改工程文件后再触发热更。
- 别名：更新文件、工程补丁

### reload_res
- 定义：热更步骤之一，通过 GM 命令 `reload_res` 重载策划配置表（res），内部对 res 文件做 MD5 差异检测后 `sharetable.loadstring` 重载，并广播 `res_reload` 事件通知各服务。
- 别名：配置重载、res重载

### reload_sproto / reload_orm_schema
- 定义：热更步骤中的协议与 ORM schema 重载开关。`reload_sproto` 通过 `reload_sproto_schema` 命令重新加载 sproto 协议定义；`reload_orm_schema` 通过 `reload_orm_schema` 命令重载 ORM schema。两者均为可选步骤，由热更配置开关控制。
- 别名：协议重载、schema重载

### clearcache
- 定义：热更步骤之一，调用 GM 命令 `clearcache` 执行 `skynet.cache.clear()` 清理 Lua 代码缓存，使后续 `require` 能加载新的 `update_files` 文件。该操作仅影响当前节点进程。
- 别名：缓存清理、Lua缓存清理
