进程入口为 `app/role/main.lua`，启动后拉起 `watchdog`、`launcher` 并监听 gate 端口；`watchdog` 作为 socket 门面，维护 fd→client 映射，将新连接通过 `gate.forward` 转交给 `login` 或具体业务 agent。

- 登录层：`app/role/login/` 下 `main.lua` 注册 sproto 模块 `login`，接收 `open/disconnect` 等命令，负责把客户端转发到 `roleagentmgr` 指定的 roleagent。
- 角色代理层：`roleagentmgr` 根据配置 `agent_count` 启动多个 `roleagent` 子服务（名称由 `roleagent_api.format_agent_name(i)` 生成），每个 roleagent 持有若干角色对象并通过 `rolemgr` 管理生命周期。
- 角色模块扩展：`roleagent/modules/` 采用“代码生成 + 插件”结构，`modules/init.lua` 由工具 `tools/gen_roleagent_modules.lua` 生成，统一注册 `role/mail/bag` 等 sproto 模块并在角色加载时初始化对应状态。
- 分布式协调：roleagent 使用 `distributed_lock` 对 `roleagent/<rid>` 加锁实现跨节点角色互斥加载，冲突时通过 `rolenode_api.calc_rolenode` 定位目标节点并调用其 `unload_role`；同时通过 `cluster_discovery.register` 向集群广播自身服务名。
- 配置隔离：`etc/role1.conf.lua` / `etc/role2.conf.lua` 分别指定不同的 `app_config_path`（`role1.app.lua` / `role2.app.lua`），从而以不同 cluster_node_name、gate_port、snowflake_machine_id 等参数独立部署多个角色节点。
