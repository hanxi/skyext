模块以 `lualib/` 下的扁平 Lua 文件作为各子系统入口（如 `log`、`orm`、`http_server`、`util`），通过 `require` 组合；`lualib-src/` 中的 C 代码（`crypto.c`、`jchash.c`、`traceback.c`）编译为共享库供 Lua 层调用。
- 启动链路：`loader.lua` 解析 `LUA_SERVICE` 与服务参数，设置 `package.path`（服务级与应用级 `lualib`），并 `require "skyext"`；`skyext.lua` 在 `skynet.init` 中按序初始化 `config` 与 `log`，同时钩住 `_G.next/table.unpack/table.concat/table.insert/table.remove`，使 ORM 文档对象能参与这些全局函数。
- 子模块分层：`log/` 通过 `bucket/` 抽象输出目标（console/file/service），由 `logger.lua` 统一调度；`orm/` 用元表实现带脏标记的 MongoDB 文档模型，配合 `schema_define.lua` 定义字段类型并在序列化时切换 `pairs` 行为；`http_server/` 暴露 `start`/`register_router` 接口，内部创建 `http_watchdog` 服务管理路由；`util/` 提供 io/path/string/table 工具。
- 依赖方向：业务服务 → `launcher.lua` → 各 API 模块（`cmd_api`、`gm_api`、`sproto_api`、`dbmgr`、`etcd`、`jwt`、`snowflake` 等）→ 底层 C 扩展或 Skynet 原生服务，单向依赖，无循环。
