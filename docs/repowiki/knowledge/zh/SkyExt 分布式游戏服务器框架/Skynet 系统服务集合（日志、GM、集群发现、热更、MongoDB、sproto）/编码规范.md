- 每个 Skynet 服务在 `skynet.start` 中先初始化自身状态，再调用 `cmd_api.dispatch(CMD)` 暴露内部命令，并通过 `gm_api.register(GM_CMD)` 暴露 GM 命令，形成统一的命令注册模式。
- GM 命令统一采用 `{ desc = "...", params = {...}, handler = function(params) return ok, result end }` 的表结构定义，handler 返回 `(ok, result)` 二元组。
- 跨服务通信优先通过 `gm_api.execute_command` 或 `skynet.call`/`send` 调用对方 CMD/GM 接口，避免直接 require 业务模块，保持服务边界清晰。
- 异步/长轮询操作（如 etcd watch、keepalive）使用 `skynet.fork` + `while true` + `skynet.sleep(WATCH_SLEEP)` 的重试循环，并用 `xpcall(..., debug.traceback)` 包裹以防协程崩溃。
- 配置全部通过 `config.get_table`/`get_number`/`get` 获取，而非硬编码，便于不同部署环境切换。
- 日志输出统一使用 `require "log"` 的 `log.info/warn/error/debug`，并在关键路径上附带结构化 key-value 字段（如 `"service"`, `"err"`, `"revision"`）。
