# 不做的事

这里记的是**做过又删掉**的东西。它们当时看着都挺合理，上线之后才发现代价在别处。写下来是为了不再实现第二遍。

## 判断标准

一个"更安全""更严谨"的设计要进框架，先过这三关：

1. **成本落在谁身上。**框架多担一点无所谓，写玩法逻辑的人每加一个功能就要多写一段样板，就不行。
2. **是不是在重造现成设施。**日志、轮转、配置、权限体系，仓库里或部署环境里已经有的，不要在旁边再立一个更差的。
3. **这道防线拦的是谁。**如果能触发它的人本来就有更高的权限，那它只是让日志更难读、让代码更难改，拦不住任何人。

## 日志脱敏层（`skyext.log.redact`）

**做过**：日志输出前按字段名把 token、password、secret 一类的值替换成 `[redacted]`。

**为什么删**：游戏服务器的日志在内网，能读到日志的人权限本来就很高，这层挡不住他。而按字段名匹配必然漏（`gm_token`、`jwt_secret`、`pwd` 都不在名单里），给的是假的安心。代价是每条日志多一次遍历，排查问题时还看不到真实值。

**现在怎么做**：不该进日志的东西，在产生它的地方就别传给 `log`。比如 etcd 的认证请求体在记日志时整个换成 `[auth body omitted]`（见 `lualib/skyext/etcd/transport.lua`），而不是指望输出层事后擦。

## ORM 版本化迁移链

**做过**：schema 带 `_version`，每次改结构要在 `migrations.lua` 里写一段 v3→v4 的升级函数，加载文档时按版本号逐级跑。

**为什么删**：这是把框架的问题摊派给写玩法的人——加一个字段而已，却要先去想"老文档怎么升上来"。而且迁移函数写错了没人拦得住，等线上数据被改坏才发现。

**现在怎么做**：运行期容忍（`orm.decode` 丢掉 schema 不认的字段、给缺的字段补零值），改动的安全性交给工具在提交前检查（`./bin/skyext schema check` 对比基线）。详见[改 ORM schema](guide/orm_schema_change.md)。

## GM 指令权限分级

**做过**：GM 账号一人一个 token，账号挂 `readonly`/`operator`/`admin` 角色，四十余条指令各标一个 `read`/`write`/`admin` 等级（不标按 `admin` 算），还能用 `gm_roles.extra` 自定义白名单。

**为什么删**：GM 口是管理员接口，`kill`、`inject`、`setenv`、`getenv`、热更都在里面，拿到 token 就等于拿到进程控制权，再怎么分级也挡不住。而账号配在每个节点的配置文件里，加人减人要改一圈配置再重启。

**现在怎么做**：框架只认一个 `gm_auth_token`，认完就执行。要分人分权、要知道是谁点的按钮，由对接这个接口的 admin 后台去做——它本来就有账号体系，多用户与角色权限也已经列在[管理后台规划](https://github.com/hanxi/skyext/blob/main/docs/plan/admin_panel.md)里。真正要守住的是 GM 端口默认只听 `127.0.0.1`。详见 [GM HTTP API](guide/gm_api.md#鉴权)。

## GM 独立审计文件

**做过**：每条 GM 指令往 `gm_audit.jsonl` 追加一行 JSON，参数按字段名脱敏，内存里留最近 100 条，另给一条 `audit` 指令查。

**为什么删**：三重问题叠在一起——它自己开了一份不轮转、每条都 `open`/`write`/`close` 的文件，比框架现成的日志 bucket（常驻句柄、带缓冲、到阈值自动切）差；它写完文件还往日志里打同一条，信息本来就在日志里；鉴权失败也写一条，而 GM 口没有限流，没凭证的人就能让这个不轮转的文件一直变大。内存里那 100 条则是进程一重启就没了，真要查的时候正好没有。

**现在怎么做**：执行完打一条 `GM command executed`，鉴权失败打一条 `GM auth failed`，走现有日志管线，轮转和保留策略是运维的事。

## 这些保留

同样是安全相关，下面这些留着，因为它们拦的是真实的失误，且不增加日常负担：

- **密钥强度校验**（`skyext.secret`）：示例值、占位符、过短的密钥直接拒绝启动相关功能。`allow_insecure_secret` 只放宽登录密钥，对 GM 无效。
- **默认只听回环**：GM 端口和 `/metrics` 端点默认绑 `127.0.0.1`。`/metrics` 本身不鉴权，暴露出去等于公开内部拓扑和业务量。
- **GM 默认关闭**：示例配置不带 `gm_auth_token`，不配就整个接口拒绝服务。
- **schema 兼容性门禁**：`./bin/skyext schema check` 在 CI 里跑，不兼容的 schema 改动进不了主干。
